## Repeated behavior and necessary distinctions

* **Cleanliness observation repeats:** `requireCleanMergeWorktreeWithRunner` (`worktree_merge_conflict_recovery.go:345`) and `worktrees.cleanWorktree` (`worktrees.go:2039`) both run `git status --porcelain=v1`. Their contracts differ: trimming and contextual dirty error versus boolean/untouched output; the transaction Git adapter may be descriptor-authorized. `gitops.WorktreeChanged` is another related observer, but its internal execution is not the same context/Runner seam. Consolidate the observation contract below the callers only after preserving their authority/error contracts; do not replace secure Git with generic path execution.
* **Ancestry predicate repeats, implementation differs:** orchestrate's `isMergeAncestorWithRunner` (:372) compares a returned merge-base SHA; worktrees uses `worktreeproof.IsAncestor` (`lifecycle.go:4211`) and native `--is-ancestor` exit classification. The proof leaf handles self-equality/memo/cancellation/exit1; orchestration propagates merge-base errors. These are consolidation candidates, not byte-equivalent delegates. Choose one explicit contract and characterize unrelated histories, command failure and cancellation before cutover.
* **Atomic publication sequence repeats:** `persistWorktreeMergeReceiptInjected` (`worktree_merge.go:2705–2743`) performs temp/create/chmod/write/file-sync/close/rename. `filewrite.WriteBytesAtomicInjected` (`atomic.go:145`) owns a similar sequence **plus post-rename directory open/sync** and a different temp pattern/injection naming. Reuse the existing leaf through an explicitly reviewed durability/error contract; a blind substitution adds a reachable error after publication and changes caller meaning. Production must not import test-only `WriteJSONAtomic`.
* **Similar fetch/sync names are not equivalent:** `fetchExactMergeTargetWithRunner` writes origin tracking refs; worktrees' `synchronizeCanonicalWithHook` (:1916) validates a held canonical descriptor and fetches an exact private ref. `syncCanonicalMergeTargetWithRunner` (terminal_sync:83) conditionally updates the checked-out target by ff-only, corroborates landing ancestry and notifies checkout update. Keep these policies distinct; share only an observation primitive that preserves ref custody and mutation ordering.
* **Proof reuse already exists:** worktrees absorbed-conflict readers use `mergeack`/`worktreeproof`; orchestrate's absorbed-conflict acknowledgement uses the same schema/hash owner. No second inverse-candidate constructor was found in inspected worktrees/worktreelanding/worktreepolicy production sources. This does not certify all workflow files as duplication-free.
