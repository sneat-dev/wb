## Reading the index

The TSV records file and line, qualified symbol, kind and receiver, export status, primary domain and proposed destination, directly detected side effects, side effects reachable within two indexed internal calls, up to eight immediate `worktrees` call dependencies with total call count, and external production references (path and CodeGrapher edge kind). Only the branch-policy rows identified above have verified current locations; other rows retain historical locations pending full regeneration. It also gives a heuristic extraction risk, notes about shared invariants and cross-domain calls, baseline statement coverage, and a move gate for calls or signature/type references that currently run against the proposed import order. A blank external-reference cell means the static index found none; it does **not** prove there are no interface, function-value, reflection, or unresolved calls.

The side-effect categories (`git`, `filesystem`, `network`, `process`, `env`, `global`) are source-pattern and bounded-call-graph indicators, not a runtime trace. In particular, `git fetch`/`push` is marked network by literal command arguments; indirect network work may be missed. Risk is a triage score based on size, effects, external references, and cross-domain calls, not an approval to move a symbol. `key_worktrees_dependencies` is a compact top-eight list; CodeGrapher remains the source for the full graph.

The supplied coverage profile is labeled for `origin/main` at `c934ae6`, before production changes to `branch_reconciliation.go`, `branch_config.go`, and `retired_archive.go`. The Go coverage format does not embed a commit SHA, so that provenance cannot be independently proved from the profile alone. Coverage for **54 callable symbols** in those three changed files is explicitly marked stale. Another **17 platform-specific callable symbols** have no block in that profile. Among the other 1,216 callable symbols, the profile marks 697 fully covered and 519 partially covered by its statement blocks. Those are per-symbol approximations from covered block start lines; they must not be read as current branch-wide coverage or as a fresh test result. `internal/worktreebranches` now owns the closed branch disposition and scope constants, `BranchEntry`, `BranchCleanupResult`, `BranchRef`, and the plain pull-request evidence DTOs. The facade preserves public DTO identity with type aliases and delegates through a `PolicyOptions` value containing only selection and planning fields. The 21 extracted bodies cover retired namespace selection and counts, display filtering and sorting, disposition and skip policy, remote PR evidence refusal, receipt formatting, protected names, peer-safe disposition, and retirement destination formatting. `worktreebranches` imports only the standard library; `worktrees` imports it, never the reverse. The facade continues to own Git and GitHub acquisition, repository discovery, cleanup apply and rechecks, quarantine transactions, and report publication. Focused tests cover all 21 leaf bodies and all 21 facade wrappers at 100% of their statements; this is not a package-wide or full-workflow coverage claim.

`internal/worktreepolicy` owns the neutral config DTOs, pure `Decode`, repository-placement policy, and retired-archive basename validation. `Decode` parses supplied bytes and accepts a **branch grammar validator parameter**; it reads no files and runs no Git. `branchConfigFile` is a facade type alias to the policy DTO used by the remaining loader and adapters; the retired-archive organization DTO is consumed directly from `internal/worktreepolicy`. `parseBranchConfig`, `repositoryPlacementPolicy`, and `validateRetiredArchiveRepositoryName` are facade adapters to the extracted functions. The separate **read-only `loadBranchConfigFile` loader** still resolves symlinks, enforces a regular file and size limit, and passes bytes to the decoder from `worktrees`; it is I/O code, not part of the pure policy package. Policy imports `repopath`, but does not import layout, retirement, branches, or the facade. `parseBranchConfig` still supplies Git-backed `validBranch`, and `ResolveRetiredArchiveTarget` still calls facade `configuredUserWorktreesConfig`. Moving those wrappers verbatim would reintroduce a layout/retirement cycle. `internal/worktreelayout` now owns the two- or three-component address grammar, clone-relative grammar, placement path arithmetic, and canonical clone lookup. Its direction is `worktrees -> worktreelayout -> repopath`; it never imports the existing `internal/layout` package. `validSafeSegment` and `validRepositorySegment` now delegate to the leaf, which uses `repopath.SafeSegment` after characterization confirmed the same ASCII segment rules. `ResolveRetiredArchiveTarget` can later depend on the neutral policy loader, while `repositoryBranchConfigAt` and Git validation stay facade adapters until the interface is explicit.

`internal/worktreeproof` is the proposed neutral receipt/proof kernel. It may own normalized SHA/target/receipt identity types and shared pure validation/formatting. The branch-local `shortSHA` body currently lives in `internal/worktreebranches` because retirement destination and receipt formatting use it; its facade wrapper remains available to other domains. A later shared proof extraction can move it below branch and landing once that import direction is established. The proof package must not import branch, landing, or the facade. Landing may emit a proof record; branch cleanup may consume it. Git-backed predicates such as `contentContained` and `isAncestor` stay behind a read-only Git proof port or in the facade until they can obey that direction. `ListResult` methods stay with the facade receiver; `LandingEvidence` and other shared proof DTOs can be aliased there for API compatibility. This removes the observed landing -> branch receipt-identity calls before branching imports landing verification.

`internal/filewrite` now owns descriptor-relative atomic/immutable byte writes, JSON codecs, no-follow reads, and their explicit fault-injection points. It already owns the create/write/sync/close/rename primitives used by those sequences, so this keeps one lower-level filesystem-write boundary instead of creating a parallel `worktreesecure` package. Eleven `worktrees` adapters retain their names for existing callers and tests; the former temporary-publication helper is deleted. `internal/worktreesecure` now owns the 20 descriptor-custody implementations for no-follow opens, containment, directory identity, private-child open/read, and no-replace movement; `internal/worktrees` keeps thin compatibility adapters. It imports only `secureopen`, `filewrite`, and `unixcompat`, never claims, retirement, layout, Git policy, or the facade. `readDirtyFileNoFollow` remains a future candidate. `dirtyCaptureManifest`, its evidence/entry/material DTOs, `collectDirtyCapture`, path/digest helpers, and capture publication stay together in retirement; the manifest embeds `DirtyWorktreeEvidence`, so placing it in secure storage would create a type dependency back into retirement. `readWorkLogClaimAt`, `readWorkLogTerminalAt`, `lockClaim`, `lockedWorkLogRun`, and the worklog run/outbox path adapters stay with claims because they return claim records or enforce claim fences. `addWorktreeAtSecureDestination`, `RunSecureCleanupGitHelper`, `gitWorktreeAddFromStageDirectory`, and `verifyPublishedWorktree` stay facade transactions until they have a leaf contract. Cleanup worktree open/report adapters stay with retirement because their signatures use cleanup handles/results. This makes claims -> filesystem storage one-way.

The intended package import order is acyclic:

```text
worktrees facade
  -> retirement -> sessions / branches -> landing / claims -> layout
  -> Git adapter -> secure storage / neutral policy / neutral proof / repopath
```

An arrow means “may import a lower layer”; same-level packages do not import each other. In particular, layout does not import retirement or claims; claims does not import sessions or retirement; landing does not import branches; secure storage does not import claims. Existing `internal/layout` and several `internal/session*` packages already import `internal/worktrees`, so implementation cannot be moved into them verbatim. Reuse existing `repopath`, `secureopen`, `filewrite`, `gitops`, `gitremote`, `githubobserver`, and `wbhome` where the import direction and trust contracts fit.

The current static calls are cyclic under broad domain ownership. Even after the targeted row corrections, several broad primary domains call each other; the destination column and move gates identify the staged ownership instead of claiming those source calls are already valid package imports. These are **source-level calls, not permitted future package imports**. The TSV's move gate identifies direct reverse calls, and the facade/port staging above is required before compiling extracted packages. `worktrees.go` still mixes path validation, Git policy, descriptor-safe publication, locks, and `Create`; moving the whole file would recreate the cycles.

## Coupling and duplicate families

The three god files are `worktrees.go` (4,667 lines; 191 indexed declarations), `lifecycle.go` (6,127 lines; 182), and `worklog.go` (3,654 lines; 162). Together they contain **535 of 1,572 declarations (34%)**. The prior graph snapshot recorded 113 cross-file calls from `lifecycle.go` into `worktrees.go`; the next largest were `session_receive.go` -> `worktrees.go` (75), `rename.go` -> `worktrees.go` (69), and `retire.go` -> `worktrees.go` (42). Refresh those call totals before using them for a later batch.

Several helper families are similar but have different trust guarantees; consolidate only with a named contract and characterization tests:

- Git execution: `git`, `gitWithExtraFiles`, `gitCanonical*`, `runCanonicalGitBytes`, `gitCanonicalPolicyBytes`, stage helpers, and `gitRawOutput` differ in held-directory authority, environment, and allowed verbs. `gitQueryMemo` only caches a narrow read-only set per command; `validBranchMemo` has a separate process-global success cache.
- Secure paths/writes: `openAbsoluteDirectoryNoFollow*`, `openDirectoryAtNoFollow`, `openPrivateChild*`, `writeBytesImmutableAt*`, `writeBytesAtomicAt*`, and `writeJSONAtomic*` split no-follow identity, idempotence, and fault-injection behavior. They are the best candidate for one lower-level storage API, with explicit atomic versus immutable modes.
- Evidence and receipts: `isAncestor`, `contentContained`, `commitTree`, `commitPatchIDs`, `absorbedLandingReceipt`, branch classification, and cleanup proofs answer related questions but do not authorize the same action. Exact head/target and recorded receipt checks must remain distinct.
- Discovery and cleanup reuse path/identity helpers across `worktrees.go`, `lifecycle.go`, `namespace.go`, and `branch_config.go`. The ten-function grammar slice is now delegated to `internal/worktreelayout`; wider discovery and cleanup trust boundaries still need explicit contracts.

`Create`, `Guard`, `List`, `Cleanup`, `Retire`, `Abort`, `Rename`, `RelocateRepository`, `ReceiveSessionBundle`, and session custody handoffs should initially remain facade orchestration: they coordinate multiple domains, locks, Git state, publication and rollback. Their option/result DTOs can remain as compatibility aliases or adapters while implementation moves behind them. Whole-file moves of `worktrees.go`, `lifecycle.go`, or `worklog.go` would create cycles and obscure these gates.

## Incremental extraction order

1. **Memo primitives only.** Move `gitQueryMemo`, its context key, `withGitQueryMemo`, lookup/key/get/put helpers, and `memoizableGitQuery` behind a narrow `internal/worktreegit` API. Preserve the read-only allowlist and command-scoped lifetime. **Do not move all of `git_query_memo.go`:** `validBranchGit` calls `trustedGitExecutable`, while the separate process-global `validBranchMemo` success cache is tied to `validBranch` in `worktrees.go`. Keep that adapter/cache with the facade until branch validation has an explicit port. The memo slice is covered in the supplied baseline and has no direct external production callers in the graph.
2. **Complete the neutral config and grammar seams.** The policy DTOs, pure decoder, repository-placement rule, and retired-archive name rule are extracted to `internal/worktreepolicy`; facade aliases and adapters preserve existing call sites. The bounded repository-address and checkout-path grammar now lives in `internal/worktreelayout`, with ten facade wrappers. Keep the read-only filesystem/symlink loader separate behind a secure-reader port or facade adapter; reading local policy is not part of the pure decoder. Retain `ResolveWorktreePlacement`, `repositoryBranchConfigAt`, `canonicalStoreHost`, `canonicalPathAddress`, and `ResolveRetiredArchiveTarget` as facade or domain wrappers until their Git, trust, and policy dependencies have explicit ports. Branch naming remains branch policy.
3. **Neutral receipt/proof kernel.** Extract shared receipt identity and pure SHA/proof validation into `internal/worktreeproof`, including the `absorbedConflictReceipt.identity` adapter used from both landing and branch code. Preserve exact target/head/source corroboration. Keep Git-backed proof checks behind an injected read-only Git port and keep `ListResult` methods in the facade. Then move landing verification before branch deletion apply, allowing branches -> landing -> proof without a return import.

After these bounded seams, move only generic descriptor/JSON primitives into secure storage and typed claim/lock adapters into claims; keep the entire dirty-capture model and collection in retirement, with `readDirtyFileNoFollow` as the lower helper; then session custody contracts and retired archive preflight; finally, move branch deletion and retirement implementations behind the facade. `LogRefresh`, `LogIntegrate`, `LogFinalize`, `LogArchive`, and the other public `Log*` verbs remain facade transactions because they coordinate locks, Git fetch/rebase/merge/abort, event writes, and recovery. At each stage, preserve exported signatures, characterize trust and rollback boundaries with focused tests, and measure compile time plus statement gain. Moving files alone does not improve coverage.

## Evidence and limits

CodeGrapher was used first for symbol lookup and call/reference discovery. This map does not claim current CodeGrapher IDs, reverse calls, or exact whole-package line coverage: its historical graph columns require a full regeneration. The compatibility-adapter notes identify the custody extraction and its current wrapper ranges; the baseline coverage columns remain historical. Other static risk, side-effect, and reverse-reference columns require a fresh graph pass before another extraction. Static calls are incomplete for interface dispatch and injected function values, and per-domain buckets are proposed ownership rather than a mechanically valid package split.
