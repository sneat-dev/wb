## Reading the index

The TSV gives current file and line, qualified symbol, kind and receiver, export status, primary domain and proposed destination, directly detected side effects, side effects reachable within two indexed internal calls, up to eight immediate `worktrees` call dependencies with total call count, and external production references (path and CodeGrapher edge kind). It also gives a heuristic extraction risk, notes about shared invariants and cross-domain calls, baseline statement coverage, and a move gate for calls or signature/type references that currently run against the proposed import order. A blank external-reference cell means the static index found none; it does **not** prove there are no interface, function-value, reflection, or unresolved calls.

The side-effect categories (`git`, `filesystem`, `network`, `process`, `env`, `global`) are source-pattern and bounded-call-graph indicators, not a runtime trace. In particular, `git fetch`/`push` is marked network by literal command arguments; indirect network work may be missed. Risk is a triage score based on size, effects, external references, and cross-domain calls, not an approval to move a symbol. `key_worktrees_dependencies` is a compact top-eight list; CodeGrapher remains the source for the full graph.

The supplied coverage profile is labeled for `origin/main` at `c934ae6`, before production changes to `branch_reconciliation.go`, `branch_config.go`, and `retired_archive.go`. The Go coverage format does not embed a commit SHA, so that provenance cannot be independently proved from the profile alone. Coverage for **54 callable symbols** in those three changed files is explicitly marked stale. Another **17 platform-specific callable symbols** have no block in that profile. Among the other 1,216 callable symbols, the profile marks 697 fully covered and 519 partially covered by its statement blocks. Those are per-symbol approximations from covered block start lines; they must not be read as current branch-wide coverage or as a fresh test result. The largest missed-statement regions in that baseline are `Retire` and `Create` (51 each), `RelocateRepository` (42), `cleanupRun.applyCleanupTask` (31), and `rollbackRenamePlan` (29). The top three domains by missed statements are shared orchestration (614), retirement (556), and claims/worklogs (524); these exclude stale and unprofiled spans.

The target totals for declarations still in `internal/worktrees` are **350 claims, 252 retirement, 220 branches, 206 facade, 186 sessions, 145 layout, 99 secure storage, 67 landing, 33 Git, 14 proof, and 2 existing `repopath`**: 1,574 overall. New declarations in `internal/worktreepolicy` are outside this inventory. They are not all ready for an immediate Go `mv`. The AST check covers declaration types and function signatures; body-inferred type dependencies still need compiler review. A row with no recorded reverse edge is not an automatic move approval.

`internal/worktreepolicy` now owns the neutral config DTOs, pure `Decode`, repository-placement policy, and retired-archive basename validation. `Decode` parses supplied bytes and accepts a **branch grammar validator parameter**; it reads no files and runs no Git. `branchConfigFile` and `retiredArchiveOrganizationConfig` are facade type aliases to those DTOs. `parseBranchConfig`, `repositoryPlacementPolicy`, and `validateRetiredArchiveRepositoryName` are facade adapters to the extracted functions. The separate **read-only `loadBranchConfigFile` loader** still resolves symlinks, enforces a regular file and size limit, and passes bytes to the decoder from `worktrees`; it is I/O code, not part of the pure policy package. Policy imports `repopath`, but does not import layout, retirement, branches, or the facade. `parseBranchConfig` still supplies Git-backed `validBranch`, and `ResolveRetiredArchiveTarget` still calls facade `configuredUserWorktreesConfig`. Moving those wrappers verbatim would reintroduce a layout/retirement cycle. `validSafeSegment` and `validRepositorySegment` are candidates for existing `internal/repopath` only after their semantics are compared with `repopath.SafeSegment`. `ResolveRetiredArchiveTarget` can then depend on the neutral policy loader, while `repositoryBranchConfigAt` and Git validation stay facade adapters until the interface is explicit.

`internal/worktreeproof` is the neutral receipt/proof kernel. It owns normalized SHA/target/receipt identity types and pure validation/formatting (`isGitObjectID`, `shortSHA`, the small `absorbedConflictReceipt` identity adapter). It must not import branch, landing, or the facade. Landing may emit a proof record; branch cleanup may consume it. Git-backed predicates such as `contentContained` and `isAncestor` stay behind a read-only Git proof port or in the facade until they can obey that direction. `ListResult` methods stay with the facade receiver; `LandingEvidence` and other shared proof DTOs can be aliased there for API compatibility. This removes the observed landing -> branch receipt-identity calls before branching imports landing verification.

`internal/worktreesecure` accepts bytes, JSON targets, names, and descriptors; it must not import claims, retirement, layout, Git policy, or the facade. The revised TSV has **zero indexed direct calls and zero AST signature/type references** from secure targets to those higher targets; an additional full-declaration AST identifier scan found no named higher-domain type references in secure function bodies. The same checks find zero layout -> retirement and zero landing -> branch back-edges in both calls and declaration types. `readPrivateRecordAt[T]`, `readJSONAt`, `openPrivateChild*`, `readDirtyFileNoFollow`, and the generic atomic/immutable writers fit that leaf. `dirtyCaptureManifest`, its evidence/entry/material DTOs, `collectDirtyCapture`, path/digest helpers, and capture publication stay together in retirement; the manifest embeds `DirtyWorktreeEvidence`, so placing it in secure storage would create a type dependency back into retirement. `readWorkLogClaimAt`, `readWorkLogTerminalAt`, `lockClaim`, `lockedWorkLogRun`, and the worklog run/outbox path adapters stay with claims because they return claim records or enforce claim fences. `addWorktreeAtSecureDestination`, `RunSecureCleanupGitHelper`, `gitWorktreeAddFromStageDirectory`, and `verifyPublishedWorktree` stay facade transactions until they have a leaf contract. Cleanup worktree open/report adapters stay with retirement because their signatures use cleanup handles/results. This makes claims -> secure storage one-way.

The intended package import order is acyclic:

```text
worktrees facade
  -> retirement -> sessions / branches -> landing / claims -> layout
  -> Git adapter -> secure storage / neutral policy / neutral proof / repopath
```

An arrow means “may import a lower layer”; same-level packages do not import each other. In particular, layout does not import retirement or claims; claims does not import sessions or retirement; landing does not import branches; secure storage does not import claims. Existing `internal/layout` and several `internal/session*` packages already import `internal/worktrees`, so implementation cannot be moved into them verbatim. Reuse existing `repopath`, `secureopen`, `filewrite`, `gitops`, `gitremote`, `githubobserver`, and `wbhome` where the import direction and trust contracts fit.

The current static calls are cyclic under broad domain ownership. Even after the targeted row corrections, several broad primary domains call each other; the destination column and move gates identify the staged ownership instead of claiming those source calls are already valid package imports. These are **source-level calls, not permitted future package imports**. The TSV's move gate identifies direct reverse calls, and the facade/port staging above is required before compiling extracted packages. `worktrees.go` still mixes path validation, Git policy, descriptor-safe publication, locks, and `Create`; moving the whole file would recreate the cycles.

## Coupling and duplicate families

The three god files are `worktrees.go` (4,725 lines; 191 indexed declarations), `lifecycle.go` (6,126 lines; 182), and `worklog.go` (3,778 lines; 163). Together they contain **536 of 1,574 declarations (34%)**. CodeGrapher records 113 cross-file calls from `lifecycle.go` into `worktrees.go`; the next largest are `session_receive.go` -> `worktrees.go` (75), `rename.go` -> `worktrees.go` (69), and `retire.go` -> `worktrees.go` (42). These are the highest-cost seams for compiling and testing extracted packages.

Several helper families are similar but have different trust guarantees; consolidate only with a named contract and characterization tests:

- Git execution: `git`, `gitWithExtraFiles`, `gitCanonical*`, `runCanonicalGitBytes`, `gitCanonicalPolicyBytes`, stage helpers, and `gitRawOutput` differ in held-directory authority, environment, and allowed verbs. `gitQueryMemo` only caches a narrow read-only set per command; `validBranchMemo` has a separate process-global success cache.
- Secure paths/writes: `openAbsoluteDirectoryNoFollow*`, `openDirectoryAtNoFollow`, `openPrivateChild*`, `writeBytesImmutableAt*`, `writeBytesAtomicAt*`, and `writeJSONAtomic*` split no-follow identity, idempotence, and fault-injection behavior. They are the best candidate for one lower-level storage API, with explicit atomic versus immutable modes.
- Evidence and receipts: `isAncestor`, `contentContained`, `commitTree`, `commitPatchIDs`, `absorbedLandingReceipt`, branch classification, and cleanup proofs answer related questions but do not authorize the same action. Exact head/target and recorded receipt checks must remain distinct.
- Discovery and cleanup reuse path/identity helpers across `worktrees.go`, `lifecycle.go`, `namespace.go`, and `branch_config.go`. Some apparent cycles are merely helpers parked in a god file. `repopath.SafeSegment` already exists; compare semantics before deduplicating `validSafeSegment` and `validRepositorySegment`.

`Create`, `Guard`, `List`, `Cleanup`, `Retire`, `Abort`, `Rename`, `RelocateRepository`, `ReceiveSessionBundle`, and session custody handoffs should initially remain facade orchestration: they coordinate multiple domains, locks, Git state, publication and rollback. Their option/result DTOs can remain as compatibility aliases or adapters while implementation moves behind them. Whole-file moves of `worktrees.go`, `lifecycle.go`, or `worklog.go` would create cycles and obscure these gates.

## Incremental extraction order

1. **Memo primitives only.** Move `gitQueryMemo`, its context key, `withGitQueryMemo`, lookup/key/get/put helpers, and `memoizableGitQuery` behind a narrow `internal/worktreegit` API. Preserve the read-only allowlist and command-scoped lifetime. **Do not move all of `git_query_memo.go`:** `validBranchGit` calls `trustedGitExecutable`, while the separate process-global `validBranchMemo` success cache is tied to `validBranch` in `worktrees.go`. Keep that adapter/cache with the facade until branch validation has an explicit port. The memo slice is covered in the supplied baseline and has no direct external production callers in the graph.
2. **Complete the neutral config seam.** The policy DTOs, pure decoder, repository-placement rule, and retired-archive name rule are now extracted to `internal/worktreepolicy`; facade aliases and adapters preserve existing call sites. Keep the read-only filesystem/symlink loader separate behind a secure-reader port or facade adapter; reading local policy is not part of the pure decoder. Retain `ResolveWorktreePlacement`, `repositoryBranchConfigAt`, and `ResolveRetiredArchiveTarget` as facade or domain wrappers until both placement and retirement can consume policy without importing each other. Then extract the pure placement grammar (`validCloneRelative`, `splitCloneRelative`, `canonical*Address`) into `internal/worktreelayout`. Branch naming remains branch policy.
3. **Neutral receipt/proof kernel.** Extract shared receipt identity and pure SHA/proof validation into `internal/worktreeproof`, including the `absorbedConflictReceipt.identity` adapter used from both landing and branch code. Preserve exact target/head/source corroboration. Keep Git-backed proof checks behind an injected read-only Git port and keep `ListResult` methods in the facade. Then move landing verification before branch deletion apply, allowing branches -> landing -> proof without a return import.

After these bounded seams, move only generic descriptor/JSON primitives into secure storage and typed claim/lock adapters into claims; keep the entire dirty-capture model and collection in retirement, with `readDirtyFileNoFollow` as the lower helper; then session custody contracts and retired archive preflight; finally, move branch deletion and retirement implementations behind the facade. `LogRefresh`, `LogIntegrate`, `LogFinalize`, `LogArchive`, and the other public `Log*` verbs remain facade transactions because they coordinate locks, Git fetch/rebase/merge/abort, event writes, and recovery. At each stage, preserve exported signatures, characterize trust and rollback boundaries with focused tests, and measure compile time plus statement gain. Moving files alone does not improve coverage.

## Evidence and limits

CodeGrapher was used first for file inventory, symbol lookup, call/reference edges, external references, and call clusters. The local Go AST was used as an exhaustive cross-check because the CLI query interface is search-result limited; it matched the graph exactly. Bounded source reads established the trust contracts for the first extraction candidates and duplicate families. The 40 changed-file TSV rows were refreshed from the current CodeGrapher SQLite store, Go AST positions, checked-out source, AST signature/type references, and the supplied baseline coverage profile; unchanged-file rows retain the earlier reviewed static summary. Repeated indexed edges were deduplicated by source, target, kind, and call site for refreshed rows. The 1,574-declaration AST inventory exactly matches the current production tree; the declaration/signature type pass found 1,314 references before cross-package filtering. A separate full-declaration identifier pass checked secure function bodies for named higher-domain types. These static checks do not replace a compiler pass after extraction. Static calls are incomplete for interface dispatch and injected function values, and per-domain buckets are proposed ownership rather than a mechanically valid package split. Review this map again immediately before further extraction if the source head has moved.
